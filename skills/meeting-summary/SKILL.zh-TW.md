# 會議摘要（通用版）

[English](SKILL.md)｜做法與實測數字：[`docs/summary-workflow.zh-TW.md`](../../docs/summary-workflow.zh-TW.md)

這是給 Claude Code 這類 AI 助手照做的流程。它不附程式：關卡要你自己寫成小腳本，因為**關卡必須是程式，不能是 AI 說「我檢查過了」**。

## 輸入

Glossline 每場會議存一份 Markdown 逐字稿，每句長這樣：

```
[14:03:12] 【電腦聲音】We can ship the first batch next Friday.
→ 我們下週五可以出第一批。
```

- `[時:分:秒]` 是電腦時鐘，不是錄音檔第幾秒。
- `【電腦聲音】` 是遠端所有人混在一起；`【麥克風】` 是自己。
- `→` 開頭的是譯文。

## 步驟

| # | 誰 | 做什麼 |
|---|---|---|
| 1 | 程式 | 複製逐字稿到工作資料夾，去掉 `→` 譯文行，產一份帶行號的版本。**不改原檔。** |
| 2 | AI | 從頭讀完整份（長的分段讀，一段都不能跳），照下方範本寫 `摘要.md`。每一條出處寫字幕時間。 |
| 3 | 程式 | 跑關卡 ①–⑤。沒過先修。 |
| 4 | 第二家 AI | 把摘要＋整份字幕（附行號）交給它，題目只問：講過頭、數字錯、漏掉、可疑當事實。每條要附字幕原文。 |
| 5 | AI | 讀它的每一條，回字幕原文核對，寫 `核對紀錄.md`；成立的改進摘要。 |
| 6 | 程式＋人 | （選配）回聽與燈號，見下方。 |
| 7 | 程式 | 跑全部關卡，全過才產交付檔。**沒過不准手動產檔。** |

## 摘要範本

```markdown
# <一行標題>

> ⚠️ 本摘要只根據開會當下的機器即時字幕寫成，沒有人回聽校對。
> ⏱️ 方括號裡是字幕上的電腦時鐘，不是錄音檔第幾分。
> 🎙️ 字幕只分得出【電腦聲音】與【麥克風】，「誰說的」是從上下文推的。

## 核心摘要
## 重點提煉            ← 5–8 條，各附時間
## 內容詳解            ← 依議題分小節，逐條附時間
## 決議事項
**字幕有定調的**
**只是提議（沒聽到有人拍板）**
## 待辦（誰／做什麼／什麼時候前）
## 出現的數字（全部未回聽，以錄音為準）
## 名字與拼法
| 稿裡寫的 | 狀態 | 說明 |      ← 只能用 🟡 偏向某個／🔴 未定案
## 可疑處
## 請去聽這幾秒
| # | 字幕時間 | 要聽什麼 |
```

## 核對紀錄格式

```markdown
# 核對紀錄（挑錯共 N 條）

1. 【成立】<改了什麼>
2. 【部分成立】<哪一半成立>；依據 [14:21:03]「字幕原文」
3. 【否決】<為什麼>；依據 [14:10:39]「字幕原文」
```

- 編號 1～N 連號，N 等於挑錯那方的條數，一條不漏。
- 【否決】和【部分成立】一定要附字幕時間和原文。不附就是憑印象否決。

## 關卡（自己寫成程式）

| # | 驗什麼 |
|---|---|
| ① | `摘要.md` 存在 |
| ② | 範本的段落都在；警語寫明「沒有人回聽」 |
| ③ | 摘要裡每個 `[時:分:秒]` 都在字幕裡找得到，而且至少 10 個 |
| ④ | 決議分成「字幕有定調」與「只是提議」兩欄 |
| ⑤ | 數字段標明「未回聽」 |
| ⑥ | 挑錯那方真的回了，且至少 1 條。**零條不算通過**，多半是它沒照格式答 |
| ⑦ | 核對紀錄對每一條都表態；否決與部分成立附字幕時間 |
| ⑧ | 摘要裡每個「✅ 已回聽（qN）」，都在人的回聽回覆裡找得到第 N 題的真答案（「聽不清」不算） |

⚠ 關卡只驗得到「每條都表態了」，**驗不到表態對不對**。那是寫的 AI 的責任：每一條都要真的回原文看。

每條關卡都寫一個故意弄壞的測試，確認它真的會擋。

## 寫的規矩

- 讀完全文才寫，不看別的版本的摘要。
- 「可能會」不寫成「會」；舉例用的假設數字不是實數。
- 字幕上聽錯的字**照原文寫、另外標 ⚠**，不准憑常識改成你覺得對的拼法。
- 引號裡放字幕原文，英文照抄，不翻譯後再加引號。
- 同一軌有好幾個遠端的人時，寫「遠端（推斷是某某）」，拿不準就別指名。
- 自己發現的可疑處，一律先加進「可疑處」和「請去聽這幾秒」表再交。

## 回聽與燈號（選配，要錄音檔）

1. 兩軌合成一個音檔；長度不等於原檔就不交（靜音被剪了）。
2. 對時間：挑頭、中、尾各一句加一句麥克風的話，讓能聽音檔的 AI 聽那幾秒，全部對上才算字幕時鐘和錄音對齊。沒對上先看機器實際聽到什麼，多半是挑的句子不好，換一句重跑。
3. 「請去聽這幾秒」表的每一段，讓能聽音檔的 AI 聽 3 輪，一批最多 5 段。
4. 程式比對字幕上的數字打燈號（寫法不同如 three 和 3 不算不一致）：🔴 三輪說法不一或收不齊；🟡 三輪一致但沒全聽到字幕的數字、或沒有數字可比（名字都在這級）；⚪ 三輪一致、字幕的數字都聽到，而且要聽的那個數字就在這段字幕裡。
5. 產回聽頁給人聽。人的回覆原文存檔，一個字不改。
6. 只有人的回覆能把一條改成「✅ 已回聽（qN）」，那條才是 🟢。

⛔ 機器重聽**只決定先聽哪裡**，不准拿它聽到的數字改摘要，也不給 🟢。三輪一致也可能錯。

## 精簡版（變體）

給整場都在、只要一份筆記的人：每個議題「討論重點 → 結論」，最後一張「誰／做什麼／什麼時候」表（沒講寫「未指定」）。
選配「可能要留意」最多 3 條。
精簡版不跑上面的關卡 2–5，改跑自己的一套：頁首警語寫明「沒有人回聽」；每個議題都有「討論重點」和「結論」；行動表每格不空；正文沒有下一段列的那些字眼與燈號符號；挑錯回了至少 1 條；核對紀錄每條都表態。一樣要送挑錯、一樣要寫核對紀錄，但正文不放時間、信心度、燈號、回聽清單（關卡擋這些字和燈號符號）。頁首的「沒有人回聽」警語照留。

## 不可以做的事

- ⛔ 寫的那一家要先實測再決定。我們實測過另一家單獨寫，決議＋待辦＋數字漏了 43%。
- ⛔ 不改字幕原檔。
- ⛔ 不把摘要裡的數字當已確認的事實轉述；要引用先回聽。
- ⛔ 把會議內容送給第二家 AI 前，先取得與會者同意。
